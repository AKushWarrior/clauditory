# Changelog

Versions follow semantic versioning. A major version changes a rule's outcome in a way that alters existing text, a minor version adds or deepens rules, and a patch version fixes wording without changing a rule.

## 2.1.0 (2026-11-05)

- Add section 11: run the bundled linter, `scripts/lint`, on substantial text before sending or saving it, and fix what it reports.
- Widen revision item 1 to cover en dashes and runs of hyphens standing in for a dash, and to put command-line flags in code formatting.

## 2.0.0 (2026-11-05)

- Switch to the serial comma, by the owner's choice.
- Deepen sections 2 to 8 with rules from the New Oxford Style Manual, the IBM Style Guide, and the Red Hat Technical Writing Style Guide, including idiomatic word choice, demonstratives that take a noun, dangling openers, list form, hyphenation, dates, quotation marks, and American spelling.
- Move technical writing to the separate technical-writing skill; section 9 now points to it.
- Widen revision item 3 to all trailing participles, extend items 7, 10, 11, and 12, and add items 13 (mechanical slips) and 14 (confusable words).

## 1.3.0 (2026-11-05)

- Base the draft-then-revise design on evidence that constraints applied while drafting thin out the answer, replacing the priming rationale.
- Ask the revision pass to keep every point while rewriting.

## 1.2.0 (2026-11-05)

- Rewrite the skill by its own rules: imperative bullets, consistent series, and shorter sentences. Add a commit-message example.

## 1.1.0 (2026-11-04)

- Extend the skill to all persisted text, including commit messages, code comments, and agent instruction files.
- Add technical-writing rules from the Google, Microsoft, and Apple style guides and the git and Linux kernel patch guides.
- Add the rule and revision item on inflated stand-ins for is and has, and drop embark and navigate from the overused-word list.

## 1.0.0 (2026-11-04)

- First version, built from the New York Times, AP, and Chicago manuals and research on machine-written prose.
